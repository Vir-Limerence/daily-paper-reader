## 摘要
为特定任务或领域定制LLM评判器，往往需要同时针对多个评估标准优化其提示。文本梯度方法能自动实现单一评判标准的优化，但它们生成的是自然语言评论，而非数值向量。因此，多任务学习（PCGrad、MGDA）的冲突解决工具包并不适用于多目标文本梯度场景。我们通过调整损失、梯度和优化器LLM共享跨任务信息的程度，测试了文本梯度优化器的五种分解模式。在10种配置中的6种里，我们观察到优化从未超越初始提示。当梯度LLM共同处理多个标准时，梯度特异性下降59%（从9.0降至3.7）。另外，我们发现将各任务指令单纯地组合进一个提示中，会使斯皮尔曼秩相关系数下降5.3%。这些结果识别出两种可分离的失败模式：优化时的梯度稀释和推理时的指令干扰，二者共同限制了利用文本反馈进行多目标评判器定制的设计空间。

## Abstract
Customizing an LLM judge to a specific task or domain often involves optimizing its prompt across multiple evaluation criteria simultaneously. Textual gradient methods automate this for a single judge criterion, however they produce natural-language critiques, not numerical vectors. Thus, the conflict-resolution toolkit of multi-task learning (PCGrad, MGDA) doesn't apply to the multi-objective textual gradient setting. We test five decomposition modes of textual gradient optimizers by varying how much cross-task information the loss, gradient and optimizer LLMs share. In 6 of 10 configurations, we observe that optimization never improves over the initial prompt. Gradient specificity drops by 59% (from 9.0 to 3.7) when the gradient LLM processes multiple criteria jointly. Separately, we observe that naively combining per-task instructions into a single prompt degrades Spearman's rho by -5.3%. These results identify two separable failure modes: optimization-time gradient dilution and inference-time instruction interference, which together constrain the design space for multi-objective judge customization using textual feedback.

### 2. 方法论
- **核心思想**：将提示优化流水线（损失计算、梯度生成、优化器更新）的三个阶段分别独立或联合处理多任务，考察不同“分解模式”对性能的影响。
- **五种分解模式**（用3字母代码表示各阶段的分离/合并）：
  - **SINGLE‑TASK**：每个任务完全独立运行。
  - **SSS**：损失、梯度、优化器均按任务分离。
  - **SSC**：损失和梯度分离，优化器合并所有梯度一起改写。
  - **SCC**：损失分离，梯度合并看到所有任务反馈后生成统一编辑建议，优化器合并。
  - **CCC**：所有阶段均合并处理。
- **过程级诊断指标**：
  - **梯度特异性（Gradient Specificity）**：由LLM评估梯度是否聚焦于单一任务（1=完全通用，10=高度任务专属）。
  - **反馈遵循度（Feedback Adherence）**：评估优化器是否忠实地将梯度建议融入新的指令。
- **Oracle 指令组合实验**：将各任务单独优化的最佳指令人工挑选出来，拼接到同一个多任务提示中并测试，以单独测量推理时的“指令干扰”效应。

### 6. 主要结论与发现
- **总体表现**：10种配置中有6种无法超越初始通用提示（“从1到5评分”）；仅 SINGLE‑TASK + MAE 验证在步骤2获得+0.031的微小改善。
- **梯度稀释**：当梯度 LLM 联合处理多任务时（SCC、CCC），梯度特异性从 **9.0 骤降至 3.7**（−59%）。优化器遵循度始终保持高位（7.8–8.8），因此瓶颈在于**梯度质量**而非优化器执行度。
- **指令干扰**：Oracle 实验表明，即便单独最优的指令组合后，性能也低于初始通用基线（¯ρ 下降 0.053），主要机制是冗长的专有化指令在组合时占有不对称的注意力预算，压制了简短指令。
- **两种模式相互独立**：梯度稀释发生在优化时，解释了 SCC/CCC 的失效；指令干扰发生在推理时，解释了 SSS/SSC 虽然生成高特异性梯度却依然停滞的现象。

### 7. 优点
- 首次对多标准文本梯度优化进行了系统性的分解研究，提出3阶段分解模式框架。
- 定义了“梯度特异性”和“反馈遵循度”两项可操作的诊断指标，成功定位失败瓶颈。
- Oracle 指令拼合实验巧妙地将推理时干扰与优化时稀释分离开来，加强了结论的说服力。
- 实验设计冻结了提示骨架，仅修改任务指令，严格隔离了结构变化带来的混淆因素。

### 8. 不足与局限
- **数据集单一**：仅在 SUMM EVAL 的小规模摘要评估任务上验证，四个维度同质性较高，未在差异更大的任务（如BRIGHTER多语言、ASAP++作文评分）上复现。
- **模型单一**：主要使用 Qwen 系列模型，虽做了 DeepSeek 梯度模型替换，但任务模型和优化器仍为 Qwen，通用性待验证。
- **统计效力**：每配置仅 N=3 次运行，限制了对小效应量（如 CCC + MAE 的+0.012）的显著性判断。
- **评估偏差**：特异性和遵循度评判本身依赖另一个 LLM（Claude），可能引入未知的系统性偏差。
- **未提供解决方案**：仅揭示了失败模式，只提出未来缓解方向，缺乏直接有效的整改手段。
