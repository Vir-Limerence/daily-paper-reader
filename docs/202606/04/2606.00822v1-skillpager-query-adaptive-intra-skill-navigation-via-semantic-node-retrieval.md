## 摘要
基于技能的LLM智能体越来越依赖长篇幅的程序文档，但全文档提示会浪费令牌并稀释对执行至关重要的信息。我们将此场景视为技能内检索，其目标是根据查询从已知技能文档中选择一个最小且执行充分的上下文。我们提出了SkillPager，这是一个两阶段框架，离线时将每个Markdown技能解析为类型化的语义节点，并利用最大边际相关性（MMR）在线进行全局的、以查询为条件的节点选择。在一个包含395个技能和1975个查询的基准测试上，SkillPager达到了78.89%的LLM评估上下文充分性，而详尽的全文档基线为82.23%，同时减少了47.04%的提示令牌。粒度消融实验表明，将相同的检索算法应用于原始的固定长度块可达到81.77%的充分性，但令牌成本增加了28.81%，这证明了效率提升是由类型化的语义粒度驱动的，而不仅仅是检索算法。在基于图的基线中，SkillPager比最强的基线高出12.16%。进一步消融表明，支持性内容在保留于候选池并自适应选择时最为有效，而不是通过静态启发式去除。这些结果将类型化的文档内检索确定为基于技能的智能体的一种独特访问问题。

## Abstract
Skill-based LLM agents increasingly rely on long procedural documents, but full-document prompting wastes tokens and dilutes information critical to execution. We study this setting as intra-skill retrieval, where the goal is to select a minimal, execution-sufficient context from a known skill document given a query. We present SkillPager, a two-stage framework that parses each Markdown skill into typed semantic nodes offline and leverages Maximal Marginal Relevance (MMR) to perform global, query-conditioned node selection online. On a benchmark of 395 skills and 1,975 queries, SkillPager achieves 78.89% LLM-judged context sufficiency, compared to 82.23% for the exhaustive full-document baseline, while reducing prompt tokens by 47.04%. A granularity ablation shows that applying the same retrieval algorithm to raw fixed-length chunks reaches a comparable 81.77% sufficiency but increases token cost by 28.81%, demonstrating that efficiency gains are driven by typed semantic granularity rather than the retrieval algorithm alone. Among graph-based baselines, SkillPager outperforms the strongest baseline by a margin of 12.16%. Further ablations show that supporting content is most effective when retained in the candidate pool and selected adaptively rather than removed by static heuristics. These results identify typed intra-document retrieval as a distinct access problem for skill-based agents.

- **问题定义**：基于技能的LLM智能体（如工具调用、程序执行）需要阅读长篇幅的Markdown技能文档，但全文档注入提示会：

  - 稀释关键执行信息（长文本中模型容易遗忘中间内容，且无关内容干扰判断）
- **场景特征**：不同于常规跨文档检索，该问题限定在“已知技能文档 + 查询”的场景，要求从单个文档内抽取**最小但执行充分的上下文**，即“技能内检索”（intra-skill retrieval）。
- **核心矛盾**：既要最大化上下文充分性（任务完成所需信息），又要最小化令牌开销；传统方法（全文档提示、固定长度截断）无法根据查询自适应平衡。

## 2. 论文提出的方法论

- **整体框架**：SkillPager，一个两阶段系统。
  - **Stage 1（离线）**：执行语义解析，将原始Markdown文档转化为**类型化的语义节点**。
    - 分割：按句子边界分片，合并冒号、条件开头等语义邻接片段，保持代码块完整。
    - 分类：LLM将每个片段归入6种类型：`step`（可执行步骤）、`example`、`param`、`precondition`、`error_handling`、`concept`（解释性背景）。
    - 关系推断：构建序列边、语义边（余弦相似度>0.85）、引用边、条件边，形成**解析节点图**，仅供基线对比，不在SkillPager在线阶段使用。
    - 缓存：节点文本、类型、嵌入向量预计算并持久化。
  - **Stage 2（在线）**：查询自适应MMR导航。
    - **候选池**：所有离线解析出的语义节点（包括`concept`）。
    - **MMR评分**：迭代选择节点，最大化边际相关性
      \[
      \text{MMR}(n) = \lambda \cdot \text{sim}(e_q, e_n) - (1-\lambda) \cdot \max_{s \in S} \text{sim}(e_s, e_n)
      \]
      其中 \(e_q, e_n, e_s\) 分别为查询、候选节点、已选节点的嵌入，\(\text{sim}\)为余弦相似度，\(\lambda = 0.7\)。
    - **早期停止**：当最佳候选的MMR分数<0时终止，但在 \(\lambda=0.7\) 时通常选至预算用完。
    - **动态预算**：根据技能节点总数自适应，\(|V(D)|\le100\) 时 \(k=20\)，否则 \(k=60\)。
    - **上下文组装**：选出的节点按原始文档顺序排列，拼接为最终提示上下文。
  - **设计理由**：
    - 解析的图拓扑稀疏、有入口偏差，图遍历效果差（全局MMR显著优于贪心遍历12.16%）。
    - 在全局MMR之上再加一阶子图增广反而增加令牌消耗且未提升充分性。
    - `concept`节点保留在候选池由MMR自适应选择，优于静态阈值过滤。

- **SkillPager在充分性与效率间取得良好平衡**：78.89% 充分性（全文档82.23%）而令牌减少47.04%，置信区间部分重叠，统计上非劣。

- **动态预算合理**：大技能需要更多节点（k=60），小技能k=20足够，边界选择不敏感。
