## 摘要
AI辅助编码代理受输入token成本的瓶颈限制。原始人工输入的两个主要问题导致了大部分开销：非英语文本的分词低效以及对话式提示中的结构熵。现有方法采取被动方式，压缩已经膨胀的上下文或在失败发生后进行干预。我们引入了一个前置的、边缘侧的提示重写中间件，它运行在开发者与云端代理之间。一个本地的Llama 3.2 (3B)模型执行跨语言翻译成英语、结构重写成紧凑的面向任务格式，以及使用正则验证的重写带回退保护措施，以确保优化后的提示永远不会比原始提示更大。我们在OMH-Polyglot上进行了评估，这是一个多语言编码基准，涵盖土耳其语、阿拉伯语、中文以及代码混合规格说明。在三个商业LLM后端上，该中间件将提示token减少34%-47%，总token减少高达18.8%，同时保持或提高了任务准确度。消融研究表明，这些收益主要来自重写阶段，而非简单的函数名提取。与LLMLingua-2在匹配的压缩率下相比，我们的方法在所有评估的后端上始终取得更优的OckScore性能。这些结果表明，主动的提示优化可以在不牺牲编码质量的情况下显著降低推理成本。

## Abstract
AI-assisted coding agents are bottlenecked by input-token cost. Two pathologies of raw human input drive much of this overhead: tokenization inefficiency for non-English text and structural entropy in conversational prompts. Existing approaches act reactively by compressing already-bloated contexts or intervening after failures occur.   We introduce a pre-flight, edge-side prompt-rewriting middleware that operates between the developer and the cloud agent. A local Llama 3.2 (3B) model performs cross-lingual translation into English, structural rewriting into a compact task-oriented format, and regex-validated rewrite-with-fallback safeguards to ensure the optimized prompt is never larger than the original.   We evaluate on OMH-Polyglot, a multilingual coding benchmark spanning Turkish, Arabic, Chinese, and code-switched specifications. Across three commercial LLM backends, the middleware reduces prompt tokens by 34-47 percent and total tokens by up to 18.8 percent while preserving or improving task accuracy. Ablation studies show that gains arise primarily from the rewriting stage rather than simple function-name extraction. Compared with LLMLingua-2 at matched compression rates, our method consistently achieves superior OckScore performance across all evaluated backends. These results demonstrate that proactive prompt optimization can substantially reduce inference costs without sacrificing coding quality.

## 1. 论文的核心问题与整体含义

- **研究动机**：AI 辅助编码代理（如 Cursor、Copilot）在处理多语言或冗长的自然语言提示时，输入 token 成本极高，主要源于两方面：
  - **分词低效**：主流 LLM 的 tokenizer 对英语优化，导致同样的语义信息在土耳其语、中文、阿拉伯语等语言中需要多 2–3 倍的 token。
  - **结构熵**：开发者习惯使用口语化、模糊的提示，引发检索增强生成（RAG）的过度检索和 agent 的冗余解码。
- **现有方法的不足**：现有 prompt 压缩或成本优化方案多为被动式（事后压缩已膨胀的上下文）、离线式（需要反复调用云端 API 搜索）或级联式（小模型失败后仍回退到原始未优化提示），均未主动在请求发出前解决 token 膨胀与结构冗余。
- **整体含义**：本文提出一种置于开发者与云端 agent 之间的边缘侧中间件，主动将原始多语言、低结构化的提示转化为紧凑的英语结构化载荷，从而实现“跨语言 token 套利”，在不降低代码生成质量的前提下，大幅降低云端推理的 token 开销。

## 2. 论文提出的方法论

- **核心思想**：利用边缘设备上的小型语言模型（SLM）作为“预飞行”层，在每次请求发送到云端之前，完成翻译和结构重写，输出一个经过验证的、确保 token 数不膨胀的紧凑 prompt。
- **关键技术细节**：
  - **跨语言 Token 套利 (Cross-Lingual Token Arbitrage)**：利用 BPE tokenizer 对英语的统计偏向，将非英语文本翻译为英语，从而减少 token 数量（如土耳其语相对英语约有 2.16 倍 token 开销，中文 2.41 倍，阿拉伯语 3.0 倍）。
  - **结构化提示重写**：
    - **Bi-Block（基准代理）**：将提示转换为 `[CONTEXT]`（固定句子，如“Python coding task; tests are authoritative.”）和 `[TASK]`（由 SLM 生成的一句或两句英文指令，后附原始 `assert` 行）。
    - **Tri-Block（IDE 扩展）**：额外增加 `[CONSTRAINTS]` 块，包含风格、命名约定等，但论文实验仅基于 Bi-Block。
  - **函数名 Oracle**：用正则表达式从 `assert` 语句中提取目标函数名，注入 `[TASK]` 顶部作为提示，帮助模型聚焦核心任务。
  - **正则验证与回退守卫**：SLM 生成结果经正则检查（防止输出为空、包含代码块或缺失标记等），最多允许两次修复尝试；若修复失败或优化后的 token 数不低于原始提示的 95%，则直接转发原始提示，确保云端账单不增加。
  - **本地模型**：使用 Llama 3.2 (3B) 通过 Ollama 运行，贪婪解码（temperature=0），预测预算 200 token。
- **流程**：开发者查询 → Ollama SLM 翻译+重写 → 正则验证+token 守卫 → 转发优化后的 prompt 至云端 API。

## 6. 论文的主要结论与发现

- **Token 节省显著**：在三个商业后端上，中间件使提示 token 减少 34–47%，总 token 减少 8.3%（gpt-3.5/gpt-4o）至 18.8%（Gemini lite）。
- **准确率不降反升**：gpt-3.5 和 gpt-4o 的准确率基本持平（差异在噪声范围内），Gemini lite 准确率从 95.00% 提升至 98.00%（+3 pp）。

- **相比 LLMLingua-2 有严格帕累托优势**：在 OckScore 指标上，本文方法在所有后端上均优于 LLMLingua-2；LLMLingua-2 在 Gemini 上准确率崩溃至 35%，总 token 反而增加，揭示了无语义保护的压缩对低能力模型的危害。
- **经济性因模型而异**：Gemini 上节省 12.4% 成本，gpt-4o 账单几乎持平，gpt-3.5-turbo 因回答长度增加反而贵了 15.1%。效益取决于输出 token 的定价权重。

## 7. 优点

- **主动优化范式**：将 token 优化从云端事后处理移至边缘侧事前处理，完全避免递归的 API 成本，并利用跨语言 token 偏向实现“套利”。
- **结构化的防呆设计**：Bi-Block 格式提供清晰的上下文与任务分离；正则守卫与 5% token 预算阈值确保优化绝不自毁，工程落地性强。
- **可解释的收益归因**：通过 names_only 等消融设计，清晰证明改善来自 SLM 的翻译和结构清洗，而非简单的关键字提取。
- **跨模型鲁棒性**：方法在 GPT-4o、GPT-3.5、Gemini lite 三个能力梯度的模型上均有效，且尤其使低能力模型受益。
- **发布基准与开源**：OMH-Polyglot 基准、中间件代码和 IDE 扩展均已开源，推动社区研究多语言场景下的 token 效率问题。
