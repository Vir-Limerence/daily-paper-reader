## 摘要
系统提示优化在不修改底层模型的情况下改进智能体行为，生成可读性强且与模型无关的指令。现有方法构建一个提示智能体来优化任务智能体的系统提示，但该提示智能体自身的系统提示却是人工设计且固定不变的。我们提出自演化提示优化（SePO），将提示智能体自身的系统提示与任务智能体的系统提示一同作为优化目标。SePO采用自指设计：单一提示智能体在开放式演化搜索中同时改进任务智能体的系统提示和自身的提示，搜索过程维护候选提示档案作为垫脚石。训练分两个阶段：预训练在多任务池上演化提示智能体，随后微调将其应用于目标任务。在涵盖数学（AIME'25）、抽象推理（ARC-AGI-1）、研究生水平科学（GPQA）、代码生成（MBPP）和逻辑谜题（数独）的五个基准测试中，SePO始终优于Manual-CoT、TextGrad和MetaSPO，相比Manual-CoT平均准确率提高了4.49个百分点。预训练获得的提示优化技能还能泛化到预训练混合任务以外的任务，而非记忆每个任务的提示。

## Abstract
System prompt optimization improves agent behavior without modifying the underlying model, yielding human-readable, model-agnostic instructions. Existing methods build a prompt agent that refines task agents' system prompts, yet leave the prompt agent's own system prompt hand-engineered and fixed. We propose Self-Evolving Prompt Optimization (SePO), which treats the prompt agent's own system prompt as an optimization target alongside task agents' system prompts. SePO adopts a self-referential design. A single prompt agent improves both task agents' system prompts and its own under an open-ended evolutionary search that maintains an archive of candidate prompts as stepping stones. Training proceeds in two stages: pre-training evolves the prompt agent on a multi-task pool, and fine-tuning then applies it to a target task. Across five benchmarks spanning math (AIME'25), abstract reasoning (ARC-AGI-1), graduate-level science (GPQA), code generation (MBPP), and logic puzzles (Sudoku), SePO consistently outperforms Manual-CoT, TextGrad, and MetaSPO, improving the average accuracy by 4.49 points compared to Manual-CoT. The prompt optimization skill from pre-training also generalizes to tasks beyond the pre-training mixture, rather than memorizing per-task prompts.

### 2. 论文提出的方法论

SePO 的核心思想是**自指设计**与**两阶段训练**，其关键技术细节和流程如下：

*   **自指设计（Self-Referential Design）**：
    *   **核心思想**：将提示智能体本身视为一个特殊的“任务智能体”，其“任务”就是优化其他智能体的提示。因此，用于优化任务智能体提示的同一套流程，也应用于优化提示智能体自身的系统提示，形成了一个闭环。
    *   **公式化**：论文将标准提示优化问题（公式1）和提示智能体自我优化问题（公式2）统一为同一种形式，仅是优化目标不同（`p` 与 `~p`）。

*   **开放式演化搜索（Open-Ended Evolutionary Search）**：
    *   **算法流程（算法1）**：该搜索算法是 SePO 的引擎，给定一个种子提示 `p(0)`，在 `G` 代内重复以下步骤：
        1.  **父代选择**：从一个存档 `A` 中，根据一个结合了得分和子代数量的软最大值函数，采样一个父代候选提示。
        2.  **子代生成**：由**提示智能体**读取当前提示的评估反馈（成功与失败案例），生成一个改进后的子代候选提示。
        3.  **评估与准入**：在验证集上评估子代提示的性能。若其得分优于父代，则将其加入存档 `A`。
    *   **存档机制**：存档 `A` 保存了历代优秀候选提示，使其成为后续优化过程的“垫脚石”，防止陷入局部最优，实现开放式演化。

*   **两阶段训练流程**：
    *   **第一阶段：预训练**：在由多个任务组成的任务池上，应用上述演化搜索来优化**提示智能体自身的系统提示**（`~p`）。此时，算法1中的“提示智能体”和“任务智能体”是同一个智能体，实现了**自指闭环**，目标是培养出具有通用提示优化技能的 `~p*`。
    *   **第二阶段：微调**：固定由预训练得到的、具备通用技能的提示智能体提示 `~p*`，针对每个下游目标任务，再次应用演化搜索来优化该**任务智能体的系统提示**（`p`）。此阶段分摊了预训练成本，并实现了技能的跨任务迁移。

*   **两种配置**：
    *   **SePO-Specialist**：预训练和微调均在同个单一任务上进行。
    *   **SePO-Generalist（默认）**：预训练在多任务混合池上进行，是论文的主打方法。任务池的选择使用一种贪心算法，平衡了任务与目标的相似度和任务间的多样性。
