## 摘要
LLM代理越来越依赖外部推理条件：提示、工具、记忆、标准操作流程、技能和框架反馈。这些资产可以在不改变模型权重的情况下改善任务执行，但通常通过启发式反思或简单地重用观察到的成功与失败来进行修正，仿佛仅凭计数就足够可靠。我们提出**贝叶斯代理**，一个原生且跨框架的框架，将可重用技能和标准操作流程视为关于冻结模型在特定提示、上下文和框架环境下是否成功的假设。贝叶斯代理记录经过验证的轨迹证据，针对每个技能维护一个特征条件化的类别后验分布，并将后验状态映射为可检查的操作，如补丁、分割、压缩、退役和探索。面向模型的提示获得可执行的护栏和失败模式补丁，同时后验摘要可供审计。使用`deepseek-v4-flash`，增量修复将SOP-Bench从80%提升至95%，Lifelong AgentBench从90%提升至100%，RealFin-Bench从45%提升至65%。我们进一步评估了贝叶斯代理的原生后端以及可选的GenericAgent、mini-swe-agent和Claude Code后端。结果涵盖了正面、负面、饱和和案例研究场景，表明代理技能进化最好被视作后验引导的框架优化，而非未校准的提示积累。源代码可在https://github.com/DataArcTech/Bayesian-Agent获取。

## Abstract
LLM agents increasingly rely on external inference conditions: prompts, tools, memory, SOPs, skills, and harness feedback. These assets can improve task execution without changing model weights, but they are often revised by heuristic reflection or by reusing observed successes and failures as if counts alone were reliable belief. We introduce \textbf{Bayesian-Agent}, a native and cross-harness framework that treats reusable skills and SOPs as hypotheses about whether a frozen model will succeed under a particular prompt, context, and harness environment. Bayesian-Agent records verified trajectory evidence, maintains a feature-conditioned categorical posterior over each skill, and maps posterior state into inspectable actions such as patch, split, compress, retire, and explore. Model-facing prompts receive executable guardrails and failure-mode patches, while posterior summaries remain available for audit. With \texttt{deepseek-v4-flash}, incremental repair improves SOP-Bench from 80\% to 95\%, Lifelong AgentBench from 90\% to 100\%, and RealFin-Bench from 45\% to 65\%. We further evaluate Bayesian-Agent's native backend and optional GenericAgent, mini-swe-agent, and Claude Code backends. The results include positive, negative, saturated, and case-study settings, suggesting that agent skill evolution is best viewed as posterior-guided harness optimization rather than uncalibrated prompt accumulation. The source code is available at https://github.com/DataArcTech/Bayesian-Agent.

## 2. 方法论：后验引导的技能进化框架
- **核心思想**：将每一个可复用的**技能或标准操作流程视为一个假设**——即在冻结的模型和特定推理环境下，该技能能否使代理成功完成任务。通过贝叶斯证据层，持续记录验证轨迹，维护每个技能的后验信念，并依据后验状态触发可检查的进化动作。
- **关键技术细节**：
  - **轨迹证据**：每次任务运行产生一个轨迹 $e_t$，包含任务上下文、成功/失败标签、成本、**验证器给出的失败模式**等。特征映射 $g(e_t)$ 将连续信号离散化为类别特征（如令牌桶、回合桶等）。
  - **贝叶斯证据模型**：采用**特征条件化的类别似然**，使用拉普拉斯平滑（$\lambda=1$）。对于技能 $h_k$，计算类别先验 $\pi_{k,t}(\ell)$ 和每个特征的似然 $\theta_{k,j,t}^{(\ell)}(v)$，相乘后归一化得到给定上下文 $z$ 下的成功后验概率 $s_{k,t}(z)$。同时保留 Beta-Bernoulli 共轭总结以便审计和保守决策。
  - **后验引导的技能动作**：根据后验状态和证据数量，触发五种明确动作：
    - **探索**：无观察或后验不确定。
    - **补丁**：同一失败模式出现至少 2 次，生成可执行的护栏。
    - **分割**：技能覆盖多种异质上下文时拆分为细粒度技能。
    - **压缩**：后验成功概率 ≥ 0.72 且观测 ≥ 3 时，保留精简版本以节省上下文。
    - **退役**：失败证据占主导（$\beta \ge 4$ 且成功概率 < 0.45）时标记为不可靠。
  - **模型界面与框架边界**：后验审计信息仅用于排序和调试，向 LLM 注入的是**可执行的技能文本**（如失败模式补丁、输出格式校验指令），而非原始概率数字。框架支持**原生后端**（简易聊天客户端与工作区工具）和**外部后端适配器**（GenericAgent、mini‑swe‑agent、Claude Code 等），只要它们能提供验证轨迹并接受技能文本。

## 7. 优点
- **不确定性量化**：将技能维护形式化为贝叶斯后验更新，避免 LLM 自身判断的不可靠性和启发式规则的主观性。

- **后验与执行面分离**：面向模型只注入可执行护栏，后验数据留作审计，兼顾了模型注意力与透明度。
- **跨框架适配性**：通过轨迹适配器接口，可将同一贝叶斯优化层应用于不同代理系统，具有较好的生态兼容性。
- **增量修复效率高**：只对先前失败的案例进行修复，不干扰已成功的运行，适合实际迭代场景。
